# v1.9 charter — Python scope/type completeness (cross-file + comprehension + protocol hooks)

**Status:** proposed. Not started.
**Branch (when started):** `kgweave/kuzu-port` (continues).
**PR target:** continues #1.

## Why v1.9 exists

v1.8 shipped four Python items: alias-aware decorator promotion, conditional
import guards, lambda capture LEGB resolution, metaclass + descriptor
protocol tagging. The retro queued five follow-ups; this slate takes the
four that fit a single slate without taking on a full new builder.

Specifically:

1. **PyComprehension free-name capture is missing.** v1.7-#5 added lambda
   captures but comprehensions (which also create scopes in Py3) carry
   no `captures` payload, so `PyScopeResolutionConnector` has nothing to
   classify for them.
2. **Capture resolution is single-file.** v1.8-#3 classifies
   `unresolved` for any name that isn't an enclosing local / module-level
   / builtin. Names imported into the module from another file in the
   same corpus could be lifted to `module-level-imported` if we had a
   corpus-wide module-export index.
3. **Descriptor detection doesn't chase inheritance.** v1.8-#4 only tags
   a `PyClass` as descriptor if it directly declares `__get__`. A class
   that inherits `__get__` from a base is missed.
4. **`__set_name__` protocol hook is unannotated.** Same shape as
   descriptor detection but for the binding-time hook.

Builder #4 in a new language remains a v1.10 candidate (own slate, size L,
own charter). CI disk-budget guard still blocked on a green full-suite run.

## Scope

### #1 — PyComprehension free-name capture
**Size:** S. **Risk:** low (walker payload addition; reuses v1.8-#3 logic).
- Walker today emits `PyComprehension` with no `captures` field. Python
  comprehensions create their own scope (since 3.x); free names inside the
  comprehension body that are not the iter-target or a local binding
  should be recorded the same way `PyLambda.captures` is.
- TDD fixture: comprehension referencing an outer-function local, a
  module-level binding, and a builtin (e.g. `len`).
- After walker emits `captures: list[str]`,
  `PyScopeResolutionConnector` should classify them automatically
  (parametrise the existing `_LambdaScopeIndexer` over
  `Lambda | Comprehension`, or rename).
- **Validates:** new walker + connector tests pass; existing
  comprehension + lambda tests still green.

### #2 — `__set_name__` protocol hook
**Size:** S. **Risk:** low.
- Walker stays pure; the connector layer detects classes with a direct
  `__set_name__` method and tags `PyClass.semantic_role =
  "set-name-hook"`. Same precedence rule as v1.7-#4 / v1.8-#4 — if a
  more specific role already exists (decorator-driven or descriptor),
  keep it.
- TDD fixtures: class with `__set_name__` only; class with both
  `__get__` + `__set_name__` (descriptor wins); class with neither.
- **Validates:** new connector tests; v1.8-#4 descriptor tests still green.

### #3 — Cross-file module-export index for capture resolution
**Size:** M. **Risk:** medium (new corpus-wide pass).
- Build a corpus-wide static index from existing `PyImport` + module-
  top-level binding rows: `{module_qualname: set[exported_name]}` and
  `{(consuming_file, local_name): origin_module_qualname}`.
- `PyScopeResolutionConnector`: when it would have written
  `kind="unresolved"` for a capture, consult the index. If the name is
  imported into the consuming module from another corpus module, write
  `kind="cross-file-import"` and `origin_module: str`.
- Closed set extension: `{local-in-enclosing, module-level, builtin,
  cross-file-import, unresolved}` (5 values; was 4).
- TDD: two-file fixture where lambda captures a `from other import foo`
  binding; assert connector tags `cross-file-import` with the right
  `origin_module`.
- **Out of scope this item:** type inference, `from X import *` (raw
  exports table only; star-imports stay `unresolved`).

### #4 — Descriptor inheritance chasing
**Size:** S. **Risk:** low.
- v1.8-#4 only checks direct PyFunction children of PyClass for
  `__get__`. Extend `PyDescriptorSemanticsConnector` to also walk
  declared bases (already in `PyClass.payload["bases"]`) and tag the
  class if any base (in the same corpus) declares `__get__`.
- Single-corpus only. Multi-corpus inheritance stays out of scope.
- TDD: class `A` with `__get__`; class `B(A)` with no methods; assert
  both get `semantic_role = "descriptor"`.
- **Validates:** new connector test; v1.8-#4 tests still green.

2. Each commit: targeted dir green at 0 failures.
3. No `--ignore` or `--deselect` of any pre-existing test.
4. v1.4 meta tests still green.
5. v1.5/v1.6/v1.7/v1.8 perf floors hold:
   - quickstart wall ≤ 10 s
   - SV writer N=1000 ≤ 3 s
   - Py writer N=1000 ≤ 6 s
6. JOURNAL retro at end with **What we did / Lessons learnt / Next moves**.

## Order of operations

1. **#1 PyComprehension free-name capture** (S, walker payload + reuse
   v1.8-#3 connector).
2. **#2 `__set_name__` hook** (S, connector-only addition with
   precedence rule).
3. **#3 cross-file module-export index** (M, the slate's headline item;
   widens capture-resolution closed set from 4 to 5).
4. **#4 descriptor inheritance chasing** (S, connector extension; lands
   last because it builds on v1.8-#4's structure and conflicts least
   with #3's index work).

Steps 1, 2, 4 are S-size connector/walker changes that ship in an hour.
Step 3 is the M item carrying the slate. Sequential dispatch — walker
and connectors are shared surfaces, parallel runs would conflict.
