# v1.6-#4 audit — py writer bulk-COPY parity

**Date:** 2026-05-24
**Subject:** `src/knowledge_graph/builders/py/writer.py`
**Reference:** `src/knowledge_graph/builders/sv/writer.py` (`_BULK_COPY_MIN_ROWS=100`,
`_write_graph_bulk`, dispatch in `write_graph`).

## Bulk-COPY path present: NO

`write_py_graph` is straight per-row Cypher:

- Each `PyNode` issues one `conn.execute(_NODE_MERGE_CYPHER, ...)` + one
  `conn.execute(_IN_ORIGIN_MERGE, ...)`.
- Each non-root issues one `conn.execute(_PARENT_OF_MERGE, ...)`.
- No `csv` / `tempfile` / `COPY FROM` usage anywhere.
- Same per-row cost (~10 ms/row) the SV writer used to pay pre-v1.5-#2.

## Plan

1. Add `tests/.../py/test_writer_perf.py` mirroring the SV variant. N=1000
   wall budget set at **≤ 2× the SV N=1000 budget = 6.0 s** per charter §4.
2. Confirm it fails (G2 red).
3. Add a bulk-COPY path inside `write_py_graph`: above
   `_BULK_COPY_MIN_ROWS=100` (reuse the SV constant), build one
   `Node` CSV + one `IN_ORIGIN` CSV + one `PARENT_OF` CSV and dispatch
   `COPY FROM` via the SV writer's `_copy_csv` helper. Keep the per-row
   loop for sub-threshold batches (the same overhead-amortisation logic
   the SV path documents).
4. Pre-delete the to-be-written `Node` ids with the SV writer's
   `_detach_delete_node_ids` so the replacement-merge contract survives
   the COPY uniqueness constraint.

Threshold counts `len(py_nodes)` (no edge graph here — PARENT_OF count
is bounded by node count). The Py builder has no `_unresolved.*`
placeholder synthesis (per-file, no cross-file semantic pass), so the
bulk path is simpler than SV's.
