# v1.5 charter — Kuzu write-path perf + builder #3 + housekeeping

**Status:** proposed. Not started.
**Branch (when started):** `kgweave/kuzu-port` (continues) or `kgweave/v1.5` (new).
**PR target:** continues #1 or opens #2 depending on review of #1 first.

## Why v1.5 exists

Two slates ago (v1.3) we fixed correctness + perf-determinism via the
`promote()` cache. Last slate (v1.4) we fixed pytest infra so the suite
stops chewing /tmp. v1.4-#4 surfaced the next bottleneck precisely:

> Kuzu's default `max_db_size = 8 TB` is sparse-allocated. On tmpfs that's
> free; on ext4 (where v1.4-#1's basetemp redirect put us) it costs
> per-test metadata + fsync. Per-test extract() went from ~30 s on tmpfs
> to 130-150 s on ext4. Quickstart subprocess test is at 240 s timeout
> with a 230 s perf floor.

Plus there's a real write-path issue v1.4-#4 also found: SV writer does
**per-row Cypher INSERT** in a loop (`writer.py:602`). Bulk COPY is
~10-100× faster. That's the headline v1.5 item.

## Scope

### #1 — Lower `max_db_size` for test stores
**Size:** S. **Risk:** low.
- Hypothesis: passing `max_db_size_bytes=256_000_000` (256 MB) when opening
  test stores eliminates most of the ext4 sparse-allocation cost.
- Verify Kuzu enforces the cap (no silent extend). If it does, every
  test fixture / quickstart default sets the small cap.
- Target: quickstart wall on ext4 drops from 130-150 s back to ≤ 30 s.
- Validates: re-run `test_quickstart_perf.py`; tighten the perf-floor
  budget from 230 s to whatever 1.5× the new measurement is.

### #2 — Bulk-COPY writer
**Size:** L. **Risk:** medium (touches `src/knowledge_graph/builders/sv/writer.py`).
- Replace the per-row `conn.execute(INSERT…)` loop with Kuzu's `COPY FROM`
  on a serialised CSV / Arrow batch.
- Preserve replacement-merge semantics on `(uri, source, corpus)`.
- TDD: every existing writer test must still pass; add a perf
  micro-bench (`tests/knowledge_graph/builders/sv/test_writer_perf.py`)
  with a budget of "writes N=1000 rows under T seconds".
- Target: 10× speedup on the bulk path, no regression on the
  small-fixture path.
- Risk: COPY semantics differ from INSERT for constraint violations;
  need to validate `_unresolved.<name>` synthetic IDs still resolve.

### #3 — Builder #3 (Python via libcst)
**Size:** L. **Risk:** medium (new builder, brand-new test corpus).
- New `src/knowledge_graph/builders/py/` mirroring the SV builder
  structure: `walker.py` (libcst visitor), `writer.py`, `build.py`,
  `semantic/`.
- New connector: Python↔Markdown reference connector (likely a thin
  reuse of the generalised SV↔MD connector from v1.3-#5, parameterised
  on the indexed-name set).
- Test corpus: small Python fixture set under
  `tests/knowledge_graph/fixtures/py/`.
- Pre-req: factor the 8-kind name index out of
  `src/knowledge_graph/connectors/__init__.py` into
  `_name_index.py` so the new builder doesn't duplicate it (v1.3
  next-move #5 reaches in here too).

### #4 — Configurable compat policy (v1.3 next-move #6)
**Size:** S. **Risk:** low.
- Add `compat: Literal["semver-major", "exact", "any"]` kwarg on
  `verify_or_migrate_schema_version`. Currently hard-coded
  `semver-major`.
- Three new tests, one per policy.

### #5 — Session-scoped `register_connector` fixture (v1.3 next-move #7)
**Size:** S. **Risk:** low.
- `register_connector` test fixture is currently function-scoped, which
  causes `BuilderConflict` cross-module collisions when two test modules
  register the same connector. Move to session-scope; the connector
  registry should already be idempotent.

### #6 — `gc_pruned` in demo exporter stats (v1.3 next-move #4)
**Size:** XS. **Risk:** none.
- One-line addition in `research/ast_experiment/scripts/export_demo_graph*.py`.
