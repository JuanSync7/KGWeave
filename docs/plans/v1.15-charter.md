# v1.15 charter — Python protocol-hook completeness + class kwargs

**Status:** proposed. Not started.
**Branch (when started):** `kgweave/kuzu-port` (continues).
**PR target:** continues #1.

## Why v1.15 exists

v1.14 closed four items at the protocol-hook + namespace edges. Three
of the four were pinning-only — current behaviour was correct but
untested. The only feature addition was v1.14-#2's
`_tag_via_metaclass` pass.

Builder #4 in a new language remains deferred (9 slates running since
v1.6, still needs language pick). CI disk-budget guard still blocked.
Cross-corpus qualname uniqueness still pending design pass.

This slate bundles four items that close out the Python protocol-hook
surface and the class-kwargs handling that emerged from v1.14-#2:

1. **Direct unit tests for `_tag_via_metaclass`.** Mirrors the v1.13-#2
   / v1.14-#1 pattern: feature added in prior slate, pin contract
   directly before further changes.
2. **`__class_getitem__` protocol hook.** Same shape as `__set_name__`
   (v1.9-#2) and `__init_subclass__` (v1.10-#4). A class declaring
   `__class_getitem__` participates in PEP 560 generic-class
   subscription. Tag `PyClass.semantic_role = "class-getitem-hook"`
   when the class declares the method directly. Inheritance via
   `chase_bases=True` (Python looks up `__class_getitem__` through
   the MRO at subscription time).
3. **Class keyword args lift in walker.** Today the walker extracts
   ONLY `metaclass=` from class definition keywords (v1.8-#4).
   `class C(Base, name="x", config="y")` carries `name` + `config`
   into `Base.__init_subclass__(cls, **kwargs)` — those are
   semantically meaningful but currently dropped. Lift them onto
   `PyClass.payload["class_kwargs"]: dict[str, str]` so connectors
   can reason about the parameterised hook surface.
4. **`@property` automatic descriptor tagging.** Slate headline.
   `@property`, `@cached_property` (functools), and `@staticmethod` /
   `@classmethod` are descriptors per the CPython data model.
   v1.8-#4 / v1.9-#4 only tag classes that DECLARE `__get__`. A
   class whose attribute is `@property`-decorated is itself NOT a
   descriptor (the decorator returns a `property` instance bound to
   the attribute, not the class). The actual descriptor in scope is
   the BUILTIN `property` class. Decision: do not tag the consumer
   class as `descriptor` for `@property` — that's a different
   relationship. Instead, surface `@property`/`@cached_property` as
   a NEW `PyFunction.semantic_role = "property-descriptor"` on the
   decorated function. This pins the relationship without
   misclassifying the enclosing class. Out of scope:
   `@staticmethod`/`@classmethod` (separate ticket if needed) and
   `@property.setter` / `@property.deleter` chaining.

## Scope

### #1 — Direct unit tests for `_tag_via_metaclass`
**Size:** XS. **Risk:** none (test addition only).
- Today: covered only by `init_subclass_metaclass.py` + external-meta
  fixture end-to-end paths.
- New `tests/knowledge_graph/connectors/test_py_init_subclass_metaclass_direct.py`:
  - Positive: metaclass in corpus + carries target role → consumer
    tagged.
  - Negative: metaclass not in corpus → consumer NOT tagged.
  - Negative: metaclass in corpus but NOT carrying the target role →
    consumer NOT tagged.
  - Precedence: consumer already has a `semantic_role` → metaclass
    pass leaves it alone.
  - Resolution: full dotted name lookup (e.g. `abc.ABCMeta`) and
    trailing-segment fallback (mirror the existing helper's behaviour).
- Use fabricated dict-shaped store fixtures (same pattern as
  v1.13-#2 / v1.14-#1).

### #2 — `__class_getitem__` protocol hook
**Size:** S. **Risk:** low (mirrors v1.10-#4 / v1.11-#4 shape).
- New connector module
  `src/knowledge_graph/connectors/py_class_getitem_semantics.py`
  mirroring `py_init_subclass_semantics.py`.
- Call shared helper: `tag_pyclass_by_method(store, "__class_getitem__",
  "class-getitem-hook", chase_bases=True)`.
- Precedence rule: skip when `semantic_role` already populated
  (descriptor / decorator-derived roles / init-subclass / set-name
  all win — class-getitem is the lowest-priority hook because it
  applies to ALL generic classes including standard library shapes).
- TDD fixtures:
  - `class_getitem_only.py`: class with `__class_getitem__` only →
    tagged.
  - `class_getitem_with_get.py`: class with both `__get__` and
    `__class_getitem__` → descriptor wins.
  - `class_getitem_inherited.py`: base declares method, subclass
    bare → both tagged via chase_bases.
- Register the connector in the connector list (find the registration
  site — likely `src/knowledge_graph/connectors/__init__.py` or a
  builder driver).

### #3 — Class keyword args lift in walker
**Size:** S. **Risk:** low (walker payload addition; closed-set extension).
- Today: walker handles `metaclass=` keyword explicitly. Other keywords
  on the class definition (PEP 487 `__init_subclass__` parameterisation)
  are dropped.
- New: extract ALL keyword arguments from `cst.ClassDef.keywords` into
  `PyClass.payload["class_kwargs"]: dict[str, str]` where the value is
  the dotted-name string of the keyword value (same `_dotted_name`
  helper used for `metaclass`). The `metaclass` key REMAINS in its
  own slot (don't move it — preserve existing contract); the new dict
  also includes `metaclass` for completeness.
- Non-name expression values (literals, calls) are recorded as their
  `repr()` or skipped — pick whichever the existing `_dotted_name`
  helper supports. Prefer "skip non-name values" to keep the dict
  closed-set (values are always dotted-name strings).
- TDD: fixture `class_kwargs.py`:
  ```python
  class Base:
      def __init_subclass__(cls, **kwargs):
          pass


  class Child(Base, name="alpha", config="beta"):
      pass
  ```
  Assert `Child.class_kwargs == {"name": "alpha"...}` — wait, the value
  is a string literal, not a dotted name. Adjust the fixture to use
  name references:
  ```python
  ALPHA = "alpha"
  BETA = "beta"
  
  class Child(Base, name=ALPHA, config=BETA):
      pass
  ```
  Assert `Child.class_kwargs == {"name": "ALPHA", "config": "BETA"}`.
  Also: `Other(Base, metaclass=MetaCls)` → both `metaclass="MetaCls"`
  in its own slot AND `metaclass` in `class_kwargs`.
- Negative: a class with no kwargs gets `class_kwargs: {}` (empty
  dict, not None — keeps the closed-set discipline tight).

### #4 — `@property` semantic role on PyFunction
**Size:** M. **Risk:** medium (connector-level; touches a new role on
PyFunction not PyClass; closed-set extension on PyFunction roles).
- Today: PyFunction has `semantic_role` for decorator-driven roles
  (registered via the decorator-promotion path). `@property` flows
  through that pipeline today — verify what (if any) role it gets.
  Likely: `decorator-derived` from the alias-aware promotion. Goal
  is to specifically identify `@property` (and `@functools.cached_property`)
  and tag the function `property-descriptor`.
- New connector `src/knowledge_graph/connectors/py_property_descriptor.py`:
  - Iterate PyFunction rows.
  - For each, inspect the `decorators` payload field.
  - If any decorator's canonical name resolves to `builtins.property`
    OR `functools.cached_property` (use the existing alias-aware
    decorator resolution from v1.8-#1), set
    `semantic_role = "property-descriptor"`.
  - Precedence: skip when a more-specific role already set. The role
    closed set on PyFunction extends; document it.
- TDD fixtures:
  - `property_descriptor_basic.py`: class with `@property` method →
    method tagged `property-descriptor`.
  - `property_descriptor_cached.py`: import functools, use
    `@functools.cached_property` → tagged.
  - `property_descriptor_aliased.py`: `from functools import cached_property as cp`,
    use `@cp` → tagged via alias resolution.
  - Negative: `@staticmethod` / `@classmethod` decorator NOT tagged
    `property-descriptor` (different decorator).
  - Negative: undecorated method NOT tagged.
- **NOT in scope:** changing PyClass tagging based on `@property`
  attributes. The consumer class is NOT a descriptor; only the
  attribute is.
