# v1.14 charter — Python protocol-hook depth + namespace edge cases

**Status:** proposed. Not started.
**Branch (when started):** `kgweave/kuzu-port` (continues).
**PR target:** continues #1.

## Why v1.14 exists

v1.13 closed four cross-file polish items: direct lift unit tests
(pinning), `__init__.py` consumer resolver edge, out-of-corpus
star-imports record-only (pinning), and the unified
`_is_namespace_participant` predicate. Three of the four were
pinning-only — current behaviour was correct but untested.

Builder #4 in a new language remains deferred (still needs language
pick — 8 slates running since v1.6). CI disk-budget guard still
blocked. Cross-corpus qualname uniqueness still flagged as
"tightly coupled to multi-corpus extract semantics" and needs a
design pass before it lands.

This slate bundles four small/medium items at the Python
protocol-hook + namespace edges:

1. **Direct unit tests for `_is_namespace_participant`.** v1.13-#4
   landed the predicate with end-to-end fixture coverage only. The
   recursive + memoised + fixtures-bucket-stop logic deserves
   boundary tests directly on the predicate before further changes
   touch it.
2. **Metaclass `__init_subclass__`.** v1.10-#4 + v1.11-#4 tag classes
   that declare `__init_subclass__` directly OR inherit it through a
   base. A class whose `metaclass=` keyword references a class with
   `__init_subclass__` is currently NOT tagged — the hook fires at
   subclass creation time but the connector doesn't model
   metaclass-as-hook-source. Add detection for `metaclass=` keyword
   pointing to a corpus class with the hook.
3. **Namespace package mid-chain with `__init__.py`.** v1.11-#1 walks
   while ancestor has `__init__.py`; v1.13-#4 walks while ancestor
   is a namespace participant. The transition between the two
   regimes is currently: hit the first ancestor without `__init__.py`
   → switch to namespace mode and continue. The reverse direction —
   namespace ancestor, then classic `__init__.py` ancestor above
   it — is unverified. Add `mid_chain/ns_outer/pkg_inner/__init__.py`
   shape and assert `pkg_inner.mod` qualname does NOT include
   `ns_outer`.
4. **Out-of-corpus base classes documented behaviour.** Surfaced
   v1.11-#2 (charter): "termination on missing or out-of-corpus bases"
   was a stated helper contract. v1.12-#4 verified termination via
   the cycle-guard test. But the SPECIFIC behaviour when a base
   IS out-of-corpus (vs missing entirely) is untested for descriptor
   inheritance + init-subclass inheritance. Slate headline. Pin
   behaviour at three connector boundaries: descriptor inherits,
   init-subclass inherits, set-name (no inheritance — negative).

## Scope

### #1 — Direct unit tests for `_is_namespace_participant`
**Size:** XS. **Risk:** none (test addition only).
- Today: only exercised via builder fixtures.
- New `tests/knowledge_graph/builders/py/test_namespace_participant.py`
  (or extend an existing direct-test file — match the codebase pattern):
  - Directory with `__init__.py` → False (classic package, not namespace).
  - Directory with `.py` file + no `__init__.py` → True.
  - Directory with subdirectory whose `.py` participates → True (recursive).
  - Directory with no `.py` files anywhere in subtree → False.
  - Fixtures-bucket-stop: `fixtures/py` returns False explicitly.
  - Depth-cap: deep nesting beyond `_NS_WALK_MAX_DEPTH` doesn't false-positive
    (use tmp_path to construct ephemeral structure).
- Use `tmp_path` for ephemeral structures so tests don't pollute the
  fixtures bucket. Clear `lru_cache` between cases (or use distinct
  paths) so memoisation doesn't leak between tests.

### #2 — Metaclass `__init_subclass__`
**Size:** S. **Risk:** low (connector-only addition; reuses helper).
- Today: `tag_pyclass_by_method("__init_subclass__", "init-subclass-hook",
  chase_bases=True)` walks ONLY the `bases` payload of each PyClass.
  A class `class C(metaclass=M)` where `M` declares `__init_subclass__`
  is not detected because `M` is in the metaclass slot, not in `bases`.
- Walker already carries `metaclass: str | None` on `PyClass.payload`
  (verify; if absent, this becomes a walker change — flag and pause).
  Assuming present: extend `py_init_subclass_semantics.py` to also
  consult the metaclass slot. New rule: a class C is tagged
  `init-subclass-hook` if (a) it declares the method directly, OR
  (b) any base in the chain declares it, OR (c) its metaclass (if
  in corpus) declares it.
- Implementation: add metaclass lookup loop after the bases loop in
  `tag_pyclass_by_method`, OR add a separate path in
  `py_init_subclass_semantics.py` that consults the metaclass slot
  independently. Prefer separate path — keeps the helper's
  bases-only contract clean.
- TDD: fixture `init_subclass_metaclass.py` with two classes — `Meta`
  declaring `__init_subclass__`, and `Klass` with `metaclass=Meta`
  and no methods. Assert both tagged.
- Negative: `Klass2(metaclass=ExternalMeta)` where `ExternalMeta` is
  not in the corpus → `Klass2` NOT tagged.

### #3 — Namespace mid-chain `__init__.py`
**Size:** S. **Risk:** low (validation against v1.13-#4 walker).
- Today: walker walks while parent has `__init__.py`; if first
  ancestor without `__init__.py` is namespace-participant, continues
  walking until a non-participant ancestor.
- Question: what happens when the WALK encounters a classic package
  (`__init__.py` present) AFTER a namespace ancestor? The classic
  walk should have STOPPED at the first non-`__init__.py` ancestor,
  meaning a classic package ABOVE a namespace package is not picked
  up. Verify this by fixture; if behaviour differs from expectation,
  pin the behaviour explicitly OR fix.
- Concrete fixture: `mid_chain/ns_outer/pkg_inner/{__init__.py,
  mod.py}`. The walk starting at `mod.py` should:
  - Parent `pkg_inner` has `__init__.py` → classic walk continues.
  - Parent's parent `ns_outer` does NOT have `__init__.py` → classic
    walk terminates here. mod.py qualname = `pkg_inner.mod`.
  - The namespace ancestor `ns_outer` is NOT included (it sits ABOVE
    the classic package).
- TDD: assert `mod.py` → `pkg_inner.mod` (NOT `ns_outer.pkg_inner.mod`).
- Out of scope: reversing the policy (treating `ns_outer.pkg_inner.mod`
  as the qualname). The current behaviour matches Python's import
  semantics — a classic package is a self-contained anchor.

### #4 — Out-of-corpus base classes documented behaviour
**Size:** M. **Risk:** medium (touches three connector boundaries;
must NOT regress v1.9-#4 / v1.10-#4 / v1.11-#4 fixtures).
- Three connector boundaries that chase bases:
  - `py_descriptor_semantics.py` (chase_bases=True since v1.9-#4)
  - `py_init_subclass_semantics.py` (chase_bases=True since v1.11-#4)
  - `py_set_name_semantics.py` (chase_bases=False — negative pin)
- Today (after v1.12-#4): `tag_pyclass_by_method` walks bases; if a
  base is not present in the corpus (e.g. `class B(SomeExternal):`),
  the lookup misses and the chain terminates cleanly. The helper
  does NOT crash. But: should `B` be tagged when its out-of-corpus
  base is KNOWN by other signals to be a descriptor? Answer for
  v1.14: NO — out-of-corpus is opaque, we cannot inspect external
  classes. Behaviour is: termination on out-of-corpus base = no tag.
- Implementation: no code change expected. This is pinning + a
  documentation comment in `_py_class_tag.py` stating the contract
  explicitly.
- TDD: three new fixture pairs:
  - `descriptor_external_base.py`: `class B(ExternalDescriptor):` with
    no method. `ExternalDescriptor` is NOT in any other fixture file.
    Assert `B` is NOT tagged `descriptor`. NEGATIVE for the chase.
  - `init_subclass_external_base.py`: same shape for `__init_subclass__`.
  - `set_name_external_base.py`: same shape for `__set_name__` (would
    fail to tag even WITH chasing — but `set_name` has
    `chase_bases=False` so the chain check never happens).
- Also: 4-hop chain where hop #3 is out-of-corpus. Assert chain
  terminates and hops 1-2 in corpus are tagged ONLY if hop #2 declares
  the method directly. Document in `_py_class_tag.py` header.
