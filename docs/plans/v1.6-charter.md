# v1.6 charter — stability cleanup + Python builder hardening

**Status:** proposed. Not started.
**Branch (when started):** `kgweave/kuzu-port` (continues) or new branch.
**PR target:** continues #1 or opens #2 depending on review of #1 first.

## Why v1.6 exists

v1.5 shipped the headline perf win (90× quickstart via bulk-COPY) and a
brand-new Python builder. In doing so it surfaced three pre-existing
issues we explicitly deferred to keep the v1.5 scope clean:

1. **md↔sv fixture pollution** via the lift/promote cache. When
   `md/test_isolation_i7.py` extracts SV fixtures with `extract(source="sv")`,
   the per-file lift/promote cache then returns the wrong root kind
   (`CompilationUnitSyntax` instead of `ModuleDeclarationSyntax`) when
   `sv/legacy_tests/rules/test_types.py` rebuilds the same fixture. 3 tests
   currently `--ignore`d to keep CI green.
2. **`test_origin_gc.py` Kuzu C++ teardown segfault** during
   `shared_kuzu_store` DETACH DELETE. Not a Python exception — Kuzu's
   native code aborts. 16 tests currently `--deselect`d.
3. **libcst coverage gaps in the Python builder.** v1.5-#3 deliberately
   shipped a v1 walker covering module / function / class / import only.
   Real Python has more.

Plus a small consistency item from v1.5-#2: the bulk-COPY writer only wired
into SV. The Python builder still goes through whatever its writer was
landed with — probably the per-row path. Worth auditing.

## Scope

### #1 — Fix md↔sv lift/promote cache pollution
**Size:** M. **Risk:** medium (touches builder cache).
- Root cause first. `git log --oneline tests/knowledge_graph/builders/sv/legacy_tests/rules/test_types.py` to confirm history; then reproduce the failure deterministically with the two tests in known order.
- Likely fix shapes (decide after diagnosis, do not pre-commit):
  - Scope the lift/promote cache by `(source, corpus)` so cross-source extracts don't share entries.
  - Reset the cache between `extract()` calls when `source` differs.
  - Make the cache key include the requested root kind, not just the file.
- Re-enable the 3 ignored tests. They must pass deterministically when
  run together AND in either order.
- **Validates:** remove the `--ignore` from any test commands; v1.4 meta
  tests still green; full SV+MD builder dirs green at 0 failures.

### #2 — Fix `test_origin_gc.py` Kuzu C++ teardown segfault
**Size:** M. **Risk:** medium (interacts with native code).
- Reproduce in isolation. Capture the abort signal + Kuzu version.
- Diagnose: likely either (a) `shared_kuzu_store` teardown order races
  with an outstanding Kuzu connection / cursor still held by a previous
  test, or (b) DETACH DELETE on the corpus subgraph hits a Kuzu bug
  with the size of node sets we're producing.
- Likely fix shapes:
  - Explicitly close all per-corpus connections / iterators before
    teardown.
  - Replace DETACH DELETE with a connection-recycling pattern (drop &
    recreate the table, or drop the database file and reopen) — slower
    but no native abort.
  - Pin a different `KGWEAVE_MAX_DB_SIZE_BYTES` for this dir if the cap
    is implicated.
- Re-enable the 16 deselected tests. Full `store/` dir green at 0 failures.
- **Validates:** `pytest tests/knowledge_graph/store/test_origin_gc.py -v`
  green; no `--deselect` needed in the v1.5 dir-scoped invocations.

### #3 — libcst Python builder coverage gaps
**Size:** L. **Risk:** low (pure additive).
- Walker today emits PyModule / PyFunction / PyClass / PyImport only.
- Add (priority order, ship in sub-commits with TDD red+green per kind):
  1. **decorators** — function and class. Both runtime and `@property` -family.
  2. **async def** — should be `PyFunction` with an `is_async=True` flag,
     not a new kind.
  3. **PEP 695 type aliases** (`type X = ...`) — new `PyTypeAlias` kind.
  4. **`if TYPE_CHECKING:` blocks** — imports inside should be flagged
     `runtime=False` on `PyImport`.
  5. **`__all__` exports** — list of names attached to `PyModule`.
  6. **type stub files** (`.pyi`) — same walker, different file extension.
  7. **match-case statements** — new `PyMatchStatement` kind.
  8. **walrus** — flag on the enclosing assignment.
  9. **comprehension scopes** — currently we don't visit comprehensions
     for inner-name binding. Add a `PyComprehension` kind.
- Each addition: new fixture(s) under `tests/knowledge_graph/fixtures/py/`,
  walker test, writer round-trip test.
- **Out of scope for v1.6:** lambda capture analysis, metaclass detection,
  descriptors, conditional imports beyond `TYPE_CHECKING`. Queue as v1.7.

### #4 — Audit Python builder writer for bulk-COPY parity
**Size:** S. **Risk:** low.
- Check whether `builders/py/writer.py` goes through the same shared
  bulk-COPY path as SV (or whether v1.5-#3 punted to per-row).
- If per-row: wire the bulk path through. The cost is one if-branch + a
  CSV serialiser for the Py kinds. Re-uses the SV bulk path infrastructure.
- Micro-bench `tests/knowledge_graph/builders/py/test_writer_perf.py`
  mirroring the SV perf test.
- **Validates:** N=1000 Python-write wall ≤ 2× the SV-write wall.

## Out of scope (deferred again)

- Full `pytest tests/` raw — still chews /tmp; dir-scoped only.
- CI disk-budget guard — still blocked on first green full-suite run.
- Lambda capture, metaclass, descriptors, conditional-imports-beyond-TYPE_CHECKING (queue for v1.7).
- Builder #4 (whatever language) — wait for v1.6 to land.

## Validation gates

1. Every sub-item has its own TDD-loop test commit BEFORE the impl commit.
2. Each commit: targeted dir green at 0 failures.
3. **No `--ignore` or `--deselect` of v1.5-known-pre-existing failures** by
   the end of v1.6. The whole point of #1 and #2 is to remove those.
4. v1.4 meta tests still green.
5. v1.5 perf floors hold (quickstart wall ≤ 10 s; SV writer N=1000 ≤ 3 s).
6. JOURNAL retro at end with **What we did / Lessons learnt / Next moves**.

## Order of operations (recommended)

1. **#1 md↔sv pollution** (M, unblocks clean full-suite runs).
2. **#2 origin_gc segfault** (M, also unblocks clean runs).
3. **#4 Python writer bulk-COPY parity** (S, mechanical reuse of #2-from-v1.5).
4. **#3 libcst coverage** (L, parallelisable per kind via subagents).

Steps 1+2 first because they're the regressions blocking a clean
`pytest tests/knowledge_graph/ -v` invocation. Step 3 is long but pure
additive and can fan out across sub-items. Step 4 is a quick win to
keep before the long-tail #3.
