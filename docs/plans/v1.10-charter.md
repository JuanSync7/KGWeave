# v1.10 charter — Python cross-file resolution polish + class-hook completeness

**Status:** proposed. Not started.
**Branch (when started):** `kgweave/kuzu-port` (continues).
**PR target:** continues #1.

## Why v1.10 exists

v1.9 widened the capture-resolution closed set from 4→5 by adding
`cross-file-import` (#3) and tagged set-name hooks (#2) + inherited
descriptors (#4). The v1.9 close-out queued six follow-ups; three of
them are direct gaps in the cross-file index that landed in v1.9-#3,
and one is a small `__init_subclass__` sibling to v1.9-#2. This slate
bundles those four. Builder #4 in a new language remains its own L-slate
(queued for v1.11). The CI disk-budget guard remains blocked on first
green full-suite raw run.

Specifically:

1. **`import x` module-object captures stay `unresolved`.** v1.9-#3
   deliberately skipped these because the captured local is the
   module object, not a member reference. They should classify as
   `module-import` so connectors can distinguish a module reference
   from a true unresolved name.
2. **Relative imports never resolve.** v1.8-#1 keeps relative imports'
   leading-dot prefix in the canonical name; v1.9-#3's index lookup
   misses them. Resolve them against the consuming module's package
   path.
3. **`from X import *` is opaque.** v1.9-#3 explicitly skipped
   star-imports. If `X` is in the corpus, its public exports should
   populate the consuming module's import-name table.
4. **`__init_subclass__` is unannotated.** Mirror v1.9-#2's
   `__set_name__` connector: tag classes that declare
   `__init_subclass__` directly with `semantic_role = "init-subclass-hook"`,
   precedence below descriptor / decorator-derived roles.

## Scope

### #1 — `module-import` capture kind
**Size:** S. **Risk:** low (closed set extension; widens 5→6).
- Walker stays pure. Connector change only.
- In `PyScopeResolutionConnector`, when a capture local resolves via the
  consuming module's `PyImport` to a canonical name that is itself a
  module qualname IN the corpus (i.e. `import a` / `import a.b`), write
  `kind="module-import"` with `origin_module: str`.
- Out-of-corpus module bindings still fall to `unresolved` (negative
  test required).
- Closed set extended to **6**: `{local-in-enclosing, module-level,
  builtin, cross-file-import, module-import, unresolved}`.
- TDD fixture pair: `module_capture_a.py` (empty target module) +
  `module_capture_b.py` (`import module_capture_a; f = lambda: module_capture_a`).
  Assert `kind=module-import`, `origin_module="module_capture_a"`.

### #2 — Relative-import package resolution
**Size:** S/M. **Risk:** low (string manipulation against the consuming
file's package path).
- Today v1.8-#1 records relative imports with their leading dots
  (`.sibling`, `..parent.foo`). The v1.9-#3 export index is keyed by
  absolute module qualname, so the lookup misses.
- New resolver helper: given consuming module qualname
  (e.g. `pkg.sub.consumer`) + relative target (`.sibling` →
  `pkg.sub.sibling`, `..other` → `pkg.other`), compute the absolute
  qualname.
- Wire into both v1.9-#3 cross-file lift AND v1.10-#1 module-import lift.
- TDD: package-shaped fixture under `tests/knowledge_graph/fixtures/py/relimport_pkg/`
  with `__init__.py`, `sibling.py` exporting `foo`, `consumer.py`
  doing `from .sibling import foo` and capturing `foo` in a lambda.
- **Out of scope:** namespace packages (PEP 420) — only file-based
  packages with `__init__.py` are considered.

### #3 — `from X import *` cross-file expansion
**Size:** M. **Risk:** medium (interacts with v1.9-#3 index + walker
payload).
- Walker must mark `PyImport` rows that originate from
  `from X import *` distinctly. Add `is_star: bool` to `PyImport.payload`.
- Connector: when building per-file `local_name → origin_module` table,
  expand each `is_star` PyImport into the origin module's public
  exports (already computed by v1.9-#3's `module_exports`).
- Underscore-prefixed names are excluded UNLESS the source module
  defined `__all__` (already on `PyModule.payload` since v1.6).
- TDD: two-file fixture, consumer does `from star_target import *`
  and captures a name in a lambda. Assert connector tags
  `cross-file-import` with the correct `origin_module`.

### #4 — `__init_subclass__` protocol hook
**Size:** S. **Risk:** low.
- New connector module `src/knowledge_graph/connectors/py_init_subclass_semantics.py`
  mirroring v1.9-#2's `py_set_name_semantics.py`.
- Tag `PyClass.semantic_role = "init-subclass-hook"` when the class
  declares `__init_subclass__` directly.
- Precedence: skip when role already set (descriptor / decorator
  promotions win).
- Direct declaration only — inheritance NOT chased for this hook
  (consistent scope with v1.9-#2; descriptor inheritance from v1.9-#4
  was its own targeted addition).
- TDD fixtures: `init_subclass_only.py`, `init_subclass_with_get.py`
  (descriptor wins), reuse `not_descriptor.py` for negative.

independent but ships last for cadence consistency.
