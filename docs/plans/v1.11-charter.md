# v1.11 charter — Python qualname depth + scope-tagging consolidation

**Status:** proposed. Not started.
**Branch (when started):** `kgweave/kuzu-port` (continues).
**PR target:** continues #1.

## Why v1.11 exists

v1.10 shipped four cross-file resolution items but uncovered two
limitations that are now blocking further Python depth:

1. **`PyModule.name` is the file stem, not a package qualname.** v1.10-#2's
   relative-import resolver works only for single-segment cases because
   it has nothing to anchor multi-segment package paths against.
   v1.9-#3 `module_exports` is keyed by stem too — meaning two
   different `utils.py` files in two different packages collide.
2. **Method-name tagging on `PyClass` is duplicated N=4 times.**
   v1.8-#4 (descriptor `__get__`), v1.9-#2 (`__set_name__`), v1.9-#4
   (inherited descriptor), v1.10-#4 (`__init_subclass__`) all walk
   PyClass→PyFunction children looking for a specific method name and
   stamping a role. The shape is identical; the only differences are
   the method name and the role string. Time to dedup.

Two follow-up items become cheap once those land:

3. **Multi-segment relative-import resolution** is naturally unblocked
   by item #1.
4. **`__init_subclass__` inheritance chasing** is naturally unblocked
   by item #2 (the helper grows an inheritance-aware variant).

Builder #4 in a new language remains a v1.12 candidate (own L-slate,
needs explicit language choice). CI disk-budget guard still blocked on
first full-suite green raw run.

## Scope

### #1 — Package-qualified `PyModule.name`
**Size:** M. **Risk:** medium (walker change with broad downstream
implications; many tests assert against `name` directly).
- Today: `PyModule.name = Path(uri).stem`. Two files at
  `pkg/a/utils.py` and `pkg/b/utils.py` both report `name="utils"`.
- New: when an ancestor directory of the file contains `__init__.py`,
  walk up while ancestors keep containing `__init__.py` and join with
  `.` for the qualname. So `pkg/a/utils.py` becomes `name="pkg.a.utils"`
  if `pkg/__init__.py` and `pkg/a/__init__.py` both exist; falls back
  to `"utils"` (the stem) if there is no `__init__.py` in the immediate
  parent (preserves current behaviour for top-level fixtures).
- Namespace packages (PEP 420 — `__init__.py` absent) explicitly OUT
  of scope. Same stem-only fallback as today.
- **Downstream:** `_build_module_exports` keys by `name`; that becomes
  qualified automatically. `_lift_to_cross_file` lookups must match.
- TDD: package-shaped fixture under
  `tests/knowledge_graph/fixtures/py/qual_pkg/{__init__.py, sub/{__init__.py, mod.py}}`
  with `mod.py` containing a top-level binding. Assert
  `name="qual_pkg.sub.mod"`. Negative: a sibling top-level fixture
  with no `__init__.py` keeps a stem-only name.
- **Out of scope:** changing how the walker derives `uri` paths,
  cross-corpus qualname collisions.

### #2 — Tag-by-method-name-on-PyClass helper
**Size:** S. **Risk:** low (mechanical refactor + dedup).
- Extract into `src/knowledge_graph/connectors/_py_class_tag.py` a
  helper `tag_pyclass_by_method(graph, method_name, role, *, chase_bases=False)`.
- Refactor four existing connectors to call it:
  - `py_descriptor_semantics.py` → `("__get__", "descriptor", chase_bases=True)` (v1.9-#4 inheritance flag preserved).
  - `py_set_name_semantics.py` → `("__set_name__", "set-name-hook", chase_bases=False)`.
  - `py_init_subclass_semantics.py` → `("__init_subclass__", "init-subclass-hook", chase_bases=False)`.
- Preserve the precedence rule (skip when `semantic_role` already
  populated) inside the helper itself.
- TDD: keep ALL existing connector tests green; add one helper-direct
  unit test asserting the precedence rule + chase_bases flag both work.

### #3 — Multi-segment relative-import resolution
**Size:** S. **Risk:** low (unblocked by #1).
- v1.10-#2's `_resolve_relative_qualname` already does the dot-segment
  math correctly. Once `PyModule.name` is qualified (item #1), the
  resolver should resolve `from .sibling import foo` inside
  `pkg.sub.consumer` to `pkg.sub.sibling` and hit the (now also
  qualified) `module_exports`.
- Bulk of this item is verifying behaviour with package fixtures
  beyond what v1.10-#2 used.
- TDD: extend the v1.11-#1 package fixture with a `consumer.py` that
  does `from .mod import name` and captures it in a lambda; assert
  the capture classifies as `cross-file-import` with the FULL
  qualname `qual_pkg.sub.mod`.
- **Validation:** v1.10-#2's existing single-segment fixture must
  still pass unchanged.

### #4 — `__init_subclass__` inheritance chasing
**Size:** S. **Risk:** low (unblocked by #2's helper).
- Today v1.10-#4 only tags classes that DIRECTLY declare
  `__init_subclass__`. After #2's helper has a `chase_bases` flag,
  this becomes a one-line flip in `py_init_subclass_semantics.py`.
- TDD: fixture pair — base class with `__init_subclass__`, subclass
  with no methods. Assert both tagged `init-subclass-hook`. Reuse the
  v1.9-#4 multi-hop pattern for a 3-level chain.
- **Out of scope:** out-of-corpus base classes; mixin precedence rules
  beyond direct declaration wins.

## Order of operations

1. **#2 helper refactor** (S, mechanical dedup, lands FIRST so #4
   becomes one-line).
2. **#1 package-qualified `PyModule.name`** (M, headline; walker change
   with breadth; lands second because it's the highest-blast-radius
   item and needs the helper-refactor stability surface to land on).
3. **#3 multi-segment relative-import resolution** (S, validation
   only — naturally unblocked by #1).
4. **#4 `__init_subclass__` inheritance chasing** (S, one-line flip on
   the v1.11-#2 helper).

Sequential dispatch — walker + connectors are shared surfaces.
Re-ordering #2 before #1 means downstream tests that currently rely on
the old non-qualified `name` get touched by exactly one commit (the
walker change), not by both the helper refactor AND the walker
change overlaid.
