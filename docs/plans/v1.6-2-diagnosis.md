# v1.6-#2 diagnosis — `test_origin_gc.py` Kuzu C++ teardown segfault

## TL;DR
Bug not reproducible at HEAD `58e1617`. All 16 tests pass deterministically,
both in isolation and as part of the full `tests/knowledge_graph/store/` run.
No `--deselect` / `--ignore` directive exists anywhere in the repo
(`Makefile`, `pyproject.toml`, `tests/**/conftest.py`, `scripts/*.sh`).

## Evidence
- Repo grep for `deselect` / `--ignore` returns only one hit:
  `pyproject.toml:59` (the `perf` marker docstring), unrelated.
- `pytest tests/knowledge_graph/store/test_origin_gc.py -v --timeout=120`
  → **16 passed in 16.16s** (exit 0, no SIGABRT/SIGSEGV).
- `pytest tests/knowledge_graph/store/ -v --timeout=120`
  → **88 passed in 126.74s** (exit 0).

## Environment
- Kuzu: **0.11.3** (Python wheel).
- Python: 3.12.13. pytest-9.0.3, pytest-timeout-2.4.0 (thread method).

## Likely reason it was historically flaky
v1.4-#2 introduced `shared_kuzu_store` with a per-test
`MATCH (n:Node|Origin) WHERE n.corpus = $c DETACH DELETE n` teardown.
Subsequent v1.5 work hardened: (a) per-test corpus-tag scoping so the
delete touches a small row set, (b) `_TEST_MAX_DB_SIZE_BYTES = 1 GiB`
so the buffer-manager has frame-group headroom under bulk-COPY load,
and (c) `~/.pytest-tmp` basetemp redirect off tmpfs. With those three
in place + Kuzu 0.11.3, the native abort no longer triggers on this box.

## Resolution
No code change required. The 16 tests are already enabled and green.
v1.6-#2 closes as **resolved by prior work** — the v1.5 hardening
(corpus-tag scoping, 1 GiB cap, basetemp redirect) was sufficient.
