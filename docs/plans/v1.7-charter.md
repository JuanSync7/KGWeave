## Why v1.7 exists

v1.6 shipped libcst coverage for 9 Python kinds (decorators / async / PEP 695 /
TYPE_CHECKING / `__all__` / `.pyi` / match-case / walrus / comprehensions) and
wired bulk-COPY through the Python writer (~10× perf parity with SV). In
doing so it surfaced four next-moves explicitly queued for v1.7, plus one
refactor that should land BEFORE the next builder is added.

## Scope

### #1 — Lift `builders/_writer_common.py` (refactor first)
**Size:** S. **Risk:** low (mechanical extract).
- `src/knowledge_graph/builders/py/writer.py` imports 5 private names from
  `sv/writer.py`: `_BULK_COPY_MIN_ROWS`, `_NODE_CSV_COLUMNS`, `_copy_csv`,
  `_detach_delete_node_ids`, `_node_row_for_csv`.
- Lift to public `src/knowledge_graph/builders/_writer_common.py` with stable
  names. SV and Py writers both import from there.
- TDD: existing tests stay green; no behavioural change.
- **Validates:** `pytest tests/knowledge_graph/builders/sv/ -v` and
  `pytest tests/knowledge_graph/builders/py/ -v` both green; perf floors hold;
  no cross-builder import remains (`grep -rn "from.*sv.writer import _" src/`
  returns nothing).
- **Why first:** unblocks adding a third builder in v1.8 without three-way
  private-name imports.

### #2 — Comprehension scope-chain attribution
**Size:** S. **Risk:** low.
- Today `PyComprehension` parents to the enclosing `PyModule`. Should parent
  to the enclosing `PyFunction` / `PyClass` / `PyComprehension` so name
  resolution can walk lexical scopes correctly.
- TDD: fixture with nested comprehensions inside a function; assert
  PARENT_OF edges go function→comprehension, not module→comprehension.
- **Validates:** new tests pass; existing builder/py tests still pass.

### #3 — Case-arm payload for `PyMatchStatement`
**Size:** S. **Risk:** low.
- Today `PyMatchStatement` carries no per-arm structure. Add `arms: list`
  payload with pattern kind (`literal` / `name` / `class` / `or` / `wildcard`)
  and bound names per arm. Enables narrowing-aware connectors in later slates.
- TDD: fixture with mixed patterns; assert arm payload shape.
- **Validates:** new tests pass; existing tests still pass.

### #4 — Decorator-aware connector semantics
**Size:** M. **Risk:** medium (cross-cutting between walker and connectors).
- Walker today records decorator names on `PyFunction`/`PyClass` payload but
  doesn't reinterpret. Promote three specific decorators at connector time
  (NOT walker time, to preserve walker purity):
  - `@dataclass` → tag `PyClass.semantic_role = "dataclass"`
  - `@pytest.fixture` → tag `PyFunction.semantic_role = "fixture"`
  - `@property` → tag `PyFunction.semantic_role = "property"`
- New connector module `src/knowledge_graph/connectors/py_decorator_semantics.py`,
  registered via the existing connector registry.
- TDD: 3 fixtures (one per decorator), assert `semantic_role` after
  `extract()`; assert no role assigned for unknown decorators.
- **Validates:** new connector tests pass; `connectors/test_py_md.py` still
  green; full `tests/knowledge_graph/connectors/ -v` green.

### #5 — Lambda capture analysis
**Size:** M. **Risk:** medium (new kind + scope semantics).
- New `PyLambda` kind. Walker emits, parents to enclosing scope (per #2
  fix), records captured free variables.
- TDD: fixture with lambdas capturing outer locals and module-level names;
  assert captures payload.
- **Validates:** new tests pass; existing tests green.
