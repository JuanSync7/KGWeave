# v1.12 charter — Python resolution edge-case cleanup

**Status:** proposed. Not started.
**Branch (when started):** `kgweave/kuzu-port` (continues).
**PR target:** continues #1.

## Why v1.12 exists

v1.11 closed three structural gaps (package-qualified `PyModule.name`,
shared `tag_pyclass_by_method` helper, multi-segment relative imports,
inheritance-chasing for `__init_subclass__`) and surfaced four small
correctness items at the edges of the resolution surface:

1. **`_resolve_relative_qualname` is correct-by-accident on escape-
   above-root.** When a relative target tries to escape above the
   consumer's package root (e.g. `from ...x import y` inside a
   2-segment package), the resolver returns a qualname that just
   happens not to match any corpus module rather than returning
   `None`. The v1.10-#2 + v1.11-#3 tests pass because the downstream
   miss falls through to `unresolved` either way, but the resolver
   itself is lying. Tightening it removes a future-correctness trap.
2. **PEP 420 namespace packages are silently treated as non-packages.**
   v1.11-#1 walks `__init__.py`-anchored package paths only. Any modern
   namespace package (no `__init__.py`) falls back to file-stem
   qualnames, defeating multi-segment relative-import resolution and
   cross-file lookups for namespace-packaged corpora.
3. **Conditional star-imports are silently flagged `is_star=True`
   without preserving their `import_guard`.** A `from X import *`
   inside `if TYPE_CHECKING:` or `try: ... except ImportError:`
   should still get `is_star=True` (walker correctness) AND carry
   the correct `import_guard` value (v1.8-#2 closed set) so the
   connector can decide whether to expand it at all.
4. **`tag_pyclass_by_method` has no direct unit tests.** v1.11-#2 dedup
   landed on the strength of three connector test surfaces that
   exercise the helper indirectly. The helper's contract
   (precedence, `chase_bases` recursion termination on missing or
   out-of-corpus bases) deserves direct coverage so refactors
   downstream don't accidentally regress it.

Builder #4 in a new language remains deferred (needs explicit language
pick on its own ticket; queued for v1.13). CI disk-budget guard still
blocked.

## Scope

### #1 — Tighten `_resolve_relative_qualname` escape-above-root
**Size:** S. **Risk:** low (resolver-only change; isolated function).
- Today: counts leading dots in `relative_target` and strips that many
  segments from the right of `consuming_module`. If `consuming_module`
  has fewer segments than the dot count would strip, the function
  returns whatever's left (sometimes a bare name, sometimes empty).
  In practice the downstream lookup misses and the capture falls to
  `unresolved` — correct outcome, wrong reason.
- New rule: leading-dot count K vs consuming-module segment count N.
  Python's relative-import semantics consume K-1 parent segments
  (the leaf module name itself doesn't count toward the chain). So
  the correct check is: if K > N (would step above the package root),
  return `None`; otherwise strip K-1 trailing segments from `consuming_module`,
  then append `relative_target` body.
  - Concrete: `consuming_module="pkg.sub.consumer"`, target=`"."` (K=1) →
    `pkg.sub` + body; with target=`".sibling"` (K=1, body=`sibling`) →
    `pkg.sub.sibling`. With target=`"..other"` (K=2, body=`other`) →
    `pkg.other`. With target=`"...x"` (K=3) inside 3-segment consumer →
    returns `x` (top-level — legitimate). K=4 inside 3-segment consumer
    → `None` (legitimate escape).
- v1.10-#2's existing escape-above-root negative test must still pass
  (it'll now pass because the resolver returns `None`, not because the
  corpus lookup misses).
- New unit tests directly on `_resolve_relative_qualname` covering:
  K=1, K=2, K=N, K=N+1 (legitimate top-level case), K>N+1 (None).

### #2 — PEP 420 namespace packages
**Size:** S/M. **Risk:** medium (changes the qualname-walk termination
condition; could surface latent test brittleness).
- Today: walker walks up while EACH ancestor has `__init__.py`. First
  `__init__.py`-less ancestor terminates.
- New: walker walks up while EITHER (a) the ancestor has `__init__.py`,
  OR (b) the ancestor contains any other `.py` files that themselves
  participate in the same package (heuristic: namespace package dir
  is one that contains at least one `__init__.py`-less subdir which
  has Python files, AND is itself under a known corpus root).
- Simpler heuristic for v1.12: walk up while the ancestor sits inside
  the consuming corpus's known fixture root AND contains at least one
  `.py` descendant. Stop at the corpus root.
- Equivalent: take the path from the corpus root to the file, drop the
  corpus root prefix, replace `/` with `.`, strip `.py`.
- New fixture: `tests/knowledge_graph/fixtures/py/ns_pkg/{sub/mod.py, sub/consumer.py}` with NO `__init__.py` anywhere. Walker test
  asserts `mod.py` gets qualname `ns_pkg.sub.mod`; capture test
  asserts `from .mod import foo` in `consumer.py` resolves to
  `ns_pkg.sub.mod`.
- Existing `qual_pkg` (with `__init__.py`) fixture stays green.
- Existing top-level stem-only fixtures (no parent dir worth walking)
  stay green.

### #3 — Conditional star-imports preserve `import_guard`
**Size:** S. **Risk:** low (walker payload combine).
- Today: walker sets `is_star=True` on `PyImport`. v1.8-#2 sets
  `import_guard` to one of `{type-checking, try-import, version-guard,
  conditional}` based on the import's enclosing structure. The two
  fields are computed independently; a `from X import *` inside
  `if TYPE_CHECKING:` will (by current walker code) have BOTH
  `is_star=True` AND `import_guard="type-checking"`. Verify this
  holds; add a test pinning it.
- Decision rule for v1.10-#3 expansion: expand star-import ONLY when
  `import_guard is None`. A type-checking-only star-import shouldn't
  contribute to runtime cross-file resolution.
- TDD: 2 new fixtures (`star_type_checking.py`, `star_try_import.py`)
  + connector tests asserting (a) walker payload combines correctly,
  (b) connector does NOT expand the guarded star.

### #4 — Direct `tag_pyclass_by_method` unit tests
**Size:** XS. **Risk:** none (test addition only).
- Promote helper test surface beyond v1.11-#2's three fixture-based
  cases.
- New `tests/knowledge_graph/connectors/test_py_class_tag_direct.py`:
  - precedence: pre-set role on a PyClass payload is preserved.
  - `chase_bases=False`: tag does NOT propagate to a subclass whose
    parent's base is NOT in corpus (out-of-corpus base = no tag).
  - `chase_bases=True`: tag propagates through a 4-hop chain.
  - `chase_bases=True`: cycle in declared bases (A→B→A) terminates
    cleanly (no infinite loop). If the current helper doesn't guard
    against cycles, that's a bug to fix.
  - `chase_bases=True`: multiple inheritance (B extends A1 and A2,
    where only A2 has the method) tags B.
