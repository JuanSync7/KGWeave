**Status:** proposed. Not started.

## Why v1.13 exists

v1.12 shipped four edge-case items: tightened `_resolve_relative_qualname`
contract, PEP 420 namespace-package qualname walk, conditional star-import
import-guard combine, and direct unit tests for `tag_pyclass_by_method`.
The close-out queued a v1.13 candidate list. With Builder #4 still
needing an explicit language pick (deferred 7 slates running since v1.6),
this slate takes the **Option A cross-file polish bundle** instead:

1. **`__init__.py` consumer edge case in `_resolve_relative_qualname`.**
   Surfaced v1.12-#1. A `from . import x` inside `pkg/__init__.py`
   itself has K=1 relative dots but the consuming module's qualname IS
   `pkg` (not `pkg.something`). Current resolver strips K-1=0 trailing
   segments — correct math — but the lookup target `pkg.x` only resolves
   if `x` is a sibling module of `__init__.py` (sibling in the same
   package directory). The slicing accidentally yields the right answer
   in single-segment cases; multi-segment `pkg/sub/__init__.py` doing
   `from .. import x` deserves direct test coverage so the resolver's
   `__init__.py`-aware behaviour is pinned.
2. **Direct unit tests for `_lift_to_module_import` /
   `_lift_to_cross_file`.** Surfaced v1.12-#1. These lift helpers carry
   the closed-set widening (5→6) and the cross-file index lookup. Today
   they are exercised only through end-to-end connector tests. Direct
   tests pin their contract before further widenings.
3. **Out-of-corpus star-imports record-only.** A `from external import *`
   where `external` is NOT in the corpus currently triggers v1.10-#3's
   expansion path, which finds nothing in `module_exports` and silently
   skips. Behaviour is correct (no false `cross-file-import`) but
   untested. Add a fixture + test that asserts: (a) the consuming
   module's captures stay `unresolved`, (b) no `cross-file-import` is
   emitted for an out-of-corpus star source.
4. **Namespace leaf with nested subpackages.** Surfaced v1.12-#2. The
   namespace heuristic uses `_is_namespace_leaf` (no `__init__.py` AND
   no subdirectories) and `_is_namespace_container` (no `__init__.py`
   AND no direct `.py` files). The boundary between "ns_pkg/sub/mod.py"
   (namespace leaf) and "ns_pkg/sub/{mod.py, inner/mod2.py}" (namespace
   container with nested ns package) is currently ambiguous: the leaf
   check rejects (subdir exists) AND the container check rejects (has
   direct `.py`). Files in such mixed directories fall back to
   stem-only qualnames. Slate headline — promote mixed-directory
   namespace ancestors to walk-eligible.

Builder #4 in a new language remains deferred (still needs language
pick; queued for v1.14). CI disk-budget guard still blocked.

## Scope

### #1 — `__init__.py` consumer edge in `_resolve_relative_qualname`
**Size:** S. **Risk:** low (resolver-only; isolated function).
- Today: `_resolve_relative_qualname("pkg", ".x")` with consumer
  qualname `pkg` (the `__init__.py`) computes K=1, retains N-K+1=1
  trailing segment(s)... wait — v1.12-#1's contract is **K leading
  dots, retain N-K segments of consumer, append body**. So for
  `consumer="pkg"`, K=1: retain 0 segments → `x` (top-level). That
  is **wrong**: `from . import x` inside `pkg/__init__.py` should
  resolve to `pkg.x`, not `x`.
- New rule: when consumer qualname ends with an implicit `__init__`
  identity (we know this because the consumer URI is literally an
  `__init__.py`), treat the consumer's full qualname as the package
  itself (no segment to strip for K=1). Concretely: if consumer is
  `pkg/__init__.py` → effective package = `pkg`; K=1 → `pkg.x`.
  K=2 → strip one segment → top-level → `x` (legitimate above-root).
  K=3 → `None`.
- Implementation: thread an `is_init_module: bool` flag through the
  resolver call site (writer/connector knows it from the URI), or
  detect from the consumer qualname's tail directly. Prefer call-site
  flag — keeps resolver pure.
- TDD: new fixture `init_consumer_pkg/{__init__.py, sibling.py}` where
  `__init__.py` does `from . import sibling`. Assert capture resolves
  to `init_consumer_pkg.sibling` as `cross-file-import`.
- Plus direct unit tests on `_resolve_relative_qualname` covering:
  consumer=`pkg`, init flag=True, K=1 (→ `pkg.x`); K=2 (→ `x`);
  K=3 (→ `None`). Consumer=`pkg.sub`, init flag=True (sub/__init__.py),
  K=1 (→ `pkg.sub.x`); K=2 (→ `pkg.x`); K=3 (→ `x`); K=4 (→ `None`).

### #3 — Out-of-corpus star-imports record-only
**Size:** S. **Risk:** low (assertion-only — current behaviour expected
to be correct; pin it).
- Today: v1.10-#3 expands star-imports via `_star_imports_for_origin`
  → `module_exports[origin_module]`. If `origin_module` is not in
  `module_exports`, the lookup returns empty / KeyError-guarded empty,
  no expansion happens. v1.12-#3 additionally skips expansion when
  `import_guard is not None`.
- New test surface: fixture `star_external_consumer.py` doing
  `from external_not_in_corpus import *` then capturing a name in a
  lambda. Assert: (a) capture stays `unresolved`, (b) no
  `cross-file-import` row emitted for that capture, (c) the `PyImport`
  row still exists with `is_star=True` (walker correctness preserved).
- If the assertion fails (e.g. silent KeyError or empty-dict access
  raises), tighten the connector's lookup to be explicitly None-safe.
  Expected outcome: green on first run; this is pinning, not fixing.

### #4 — Namespace leaf with nested subpackages
**Size:** S/M. **Risk:** medium (changes namespace walk eligibility;
could re-qualify previously stem-only files).
- Today: `_is_namespace_leaf` requires no subdirectories; mixed
  directories (containing both `.py` files AND subdirectories, all
  without `__init__.py`) fail both `_is_namespace_leaf` and
  `_is_namespace_container`. Files in such dirs fall back to stem-only
  qualnames.
- New: treat a directory as namespace-walk-eligible if it has no
  `__init__.py` AND (it contains any `.py` file OR it contains any
  subdirectory that is itself namespace-walk-eligible). Equivalent: a
  directory participates in a namespace package if any descendant
  (within depth cap) contains Python source.
- Implementation: replace the leaf/container split with a single
  `_is_namespace_participant(d)` predicate; walker walks up while
  ancestor satisfies it, stops at first ancestor that fails OR at
  first ancestor with `__init__.py` (in which case the classic
  v1.11-#1 walk takes over) OR at filesystem root OR at depth cap.
- Keep `_NS_WALK_MAX_DEPTH = 8` and `cur != cur.parent` guards.
- Keep `lru_cache(maxsize=512)` memoisation on the new predicate.
- Critical: **must not** re-qualify files in
  `tests/knowledge_graph/fixtures/py/` flat fixture bucket (the bucket
  itself contains many `.py` files but is not a namespace package —
  it's a flat fixture root). Solution: gate the walk on the consumer
  corpus's known root, OR ensure the walk terminates at a corpus-root
  marker. Simplest: stop the walk when the ancestor is exactly the
  fixtures root (heuristic: ancestor name == `py` and grandparent
  name == `fixtures`). Better: stop when the ancestor contains a
  marker file or when its parent fails the namespace-participant
  predicate.
- TDD fixture: `ns_nested/sub/{mod.py, inner/mod2.py}` with NO
  `__init__.py` at any level. Walker test asserts `mod.py` →
  `ns_nested.sub.mod` AND `mod2.py` → `ns_nested.sub.inner.mod2`.
- Negative test: an existing flat fixture (e.g. `module_capture_a.py`)
  still gets stem-only qualname (`module_capture_a`), not
  `py.module_capture_a` or worse.
- Existing v1.12-#2 `ns_pkg/sub/{mod.py, consumer.py}` stays green.
